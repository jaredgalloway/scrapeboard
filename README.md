# scrapeboard

The *Hello, world* of a data-scraping application: three upstreams of three
different kinds are fetched on demand (or on a schedule, if you flip it on),
appended to plain CSV tables, and rendered as a live, interactive, public
dashboard on GitHub Pages. No server, no database, no cost.

**Live dashboard:** <https://jaredgalloway.github.io/scrapeboard/>

| Source | Kind of scraping it demonstrates | What we keep |
|---|---|---|
| [Open-Meteo](https://open-meteo.com) | JSON API, no authentication | current temperature, humidity, wind for six cities |
| [Hacker News](https://news.ycombinator.com) front page | HTML built for humans, parsed with BeautifulSoup | rank, title, points, comments for the top 30 |
| [GitHub REST API](https://docs.github.com/en/rest) | JSON API with an **API key** read from the environment | stars, forks, open issues for six repos |

A GitHub Actions job runs `pixi run scrape`, commits the new rows back to this
repo, runs `pixi run build`, and deploys `site/` to GitHub Pages. Your laptop
runs the exact same two commands. Scraping is **on demand** (a button, or
`pixi run scrape-remote`); the six-hourly schedule is written but switched off.
See [docs/operations.md](docs/operations.md#running-the-scraper) to run it or
turn the schedule back on.

```
                 ┌──────────── on demand (schedule available, currently off) ────────────┐
 upstream ─fetch─▶ data/raw/<source>/<run>.json ─parse─▶ data/tidy/<source>.csv ─build─▶ site/data/*.json ─deploy─▶ GitHub Pages
 (API / HTML)      immutable snapshot                    append-only table              dashboard feed             the URL above
```

## Quick start

Requires only [pixi](https://pixi.sh) (`brew install pixi` or `curl -fsSL https://pixi.sh/install.sh | sh`).
Everything else, Python included, is installed into `./.pixi/` by the first command.

```bash
git clone https://github.com/jaredgalloway/scrapeboard && cd scrapeboard
pixi install            # build the environment from pixi.lock (one time)
pixi run pipeline       # scrape all three sources, then build the site feeds
pixi run serve          # open http://localhost:8000
```

`make` works too and maps one-to-one (`make help` lists everything).

## Commands

| `pixi run …` | `make …` | What it does |
|---|---|---|
| `scrape` | `scrape` | Fetch every source, write a raw snapshot, append tidy rows, log the run. `-s NAME` limits to one source. |
| `build` | `build` | Turn `data/tidy/*.csv` into `site/data/*.json` + `manifest.json` + `runs.json`. |
| `pipeline` | `pipeline` | `scrape` then `build`; exactly what CI runs. |
| `scrape-remote` | `scrape-remote` | Queue one scrape → commit → build → deploy run on GitHub Actions. Needs the `gh` CLI. |
| `serve` | `serve` | Static file server for `site/` on port 8000. |
| `sources` | | List registered sources. |
| `test` | `test` | Offline tests against saved fixtures. No network. |
| `lint` / `fmt` | `lint` / `fmt` | Ruff check + format (and auto-fix). |
| `check` | `check` | `lint` + `test`; the CI quality gate. |

Set `GITHUB_TOKEN` in your shell to raise the GitHub API limit from 60 to
5 000 requests/hour. It is optional locally and automatic in CI.

## Repository layout

```
config.yml               what to scrape (cities, repos, URLs) — data, not code
scrapeboard/
  sources/               one module per upstream; each has fetch() and parse()
  pipeline.py            raw → tidy → site/data orchestration; run log
  cli.py                 `scrapeboard scrape|build|serve|sources`
  paths.py, http.py      filesystem layout; a polite HTTP session (UA, timeout, retries)
data/
  raw/<source>/          one immutable snapshot per run (json/html)   ← committed by CI
  tidy/<source>.csv      one row per observation, append-only          ← committed by CI
  runs.jsonl             one line per (run, source): ok/fail, rows, seconds
site/
  index.html, app.js, styles.css   the dashboard (Plotly.js, no build step)
  data/                  generated by `build`; gitignored, rebuilt by CI every run
tests/                   pytest; fixtures/ holds saved upstream payloads
.github/workflows/
  pipeline.yml           scrape → commit → build → deploy (manual; cron off; push = deploy only)
  ci.yml                 lint + tests on pull requests
docs/                    the long-form explanations, see below
pixi.toml, pixi.lock     environment + tasks; Makefile wraps the tasks
```
